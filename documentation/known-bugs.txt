ROUND 3 FIXES (2026-04-19)
==========================

HIGH
----

#61 FIXED -- http.cpp page_catf() truncation corrupted HTML output.
    When vsnprintf overflowed the page_buf, n returned the full
    intended length so the guard `page_pos + n < sizeof(page_buf)`
    evaluated false and page_pos did not advance. The next
    page_catf call overwrote the truncated bytes, producing
    garbled HTML (visible on /dir and the partitions page). Fixed
    by clamping n to what was actually written and advancing
    page_pos unconditionally.

#62 FIXED -- cue.cpp elapsed_ms wrapped after ~49 days of playback.
    uint32_t (now_ms - music_start_ms) overflowed, causing cues
    to mis-match or stop firing during very long sessions.
    Lifted elapsed_ms and effective_start to 64-bit throughout
    the comparison.

#63 FIXED -- wasm_wrapper.cpp leaked host state on m3_RunStart failure.
    File slots, string pool, low heap, and wasm_current_path
    weren't reset on the m3_RunStart error path, so the next run
    inherited dirty state. Factored cleanup into
    wasm_cleanup_runtime() and called it from both the error and
    success paths.

#64 FIXED -- conez_wifi.cpp WiFi byte counters could tear on dual-core.
    volatile uint32_t s_tx_bytes/s_rx_bytes were load-add-stored
    from concurrent LWIP callbacks; a preempting core could lose
    an increment. Switched to std::atomic<uint32_t> with
    fetch_add(memory_order_relaxed).

MEDIUM
------

#65 FIXED -- c2wasm cw_malloc/realloc/calloc returned NULL on OOM.
    Many call sites used the result without checking. Wrapped both
    the embedded (cw_fatal + longjmp) and standalone (fprintf +
    exit) allocators to abort on NULL; callers are now guaranteed
    a valid pointer.

#66 FIXED -- c2wasm buf.c capacity doubling could overflow int.
    `while (nc < b->len + need) nc *= 2;` on a large-enough
    capacity wrapped to a negative value, causing an infinite
    loop or allocation failure. Added INT_MAX/2 guard that
    calls cw_fatal.

#67 FIXED -- WASM file_seek accepted any offset without validation.
    A negative or out-of-range offset could leave the FILE* in
    an undefined state. Now computes the target via ftell+fstat
    and rejects offsets that would move outside [0, filesize].

#68 FIXED -- psram.cpp had 8 unbounded `while (GPSPI2.cmd.X) ;` spins.
    If the SPI2 peripheral hung, the calling task looped forever.
    Added SPI2_WAIT(cond) macro (1M-iter cap ~= 4ms at 240MHz)
    and replaced all 8 spins.

#69 FIXED -- Telnet IAC subnegotiation could lock a client in state 3.
    A peer sending unterminated IAC SB payload would consume
    bytes indefinitely. Added iac_sb_bytes counter per client,
    aborted after 256 bytes.

#70 FIXED -- NMEA RMC/GGA overwrote lat/lon on bad-fix modes.
    RMC mode E/N/S or GGA quality 6-8 correctly left
    s_has_fix=false, but position was still copied to d->lat /
    d->lon. Consumers that forgot to check location_valid saw
    garbage coordinates (e.g. from dead-reckoning drift).
    Now only overwrite lat/lon when s_has_fix is true; the
    last known good position is preserved.

#71 FIXED -- datetime_to_epoch_ms only validated month.
    Garbage day/hour/minute/second in NMEA produced wildly
    wrong epochs. Now range-checks year (1970-2099), month
    (1-12), day (1-31), hour (0-23), minute (0-59), second
    (0-60 for leap); returns 0 on invalid input.

#72 FIXED -- config_save and config_set_field had no locking.
    A cross-task reader could observe a half-written string
    field (wifi_ssid, mqtt_broker, etc.). Added config_mutex
    created in config_init; take/give around set_field (per
    write) and save (snapshot loop).

#73 FIXED -- editor_save was not atomic.
    A crash or power loss mid-save left the file truncated or
    empty. Now writes to <path>.tmp, flushes+closes, then
    renames into place; unlinks the tmp on any error.

LOW
---

#74 FIXED -- led_setup() could leak CRGB arrays on re-entry.
    Safe today (called only from main setup()), but a future
    config-reload path would leak the four buffers. Now
    delete[] the old arrays before re-allocating; rmt_init()
    guarded by a static bool so RMT channels and encoder can't
    double-create.

#75 FIXED -- led_push_hw's grb_buf was shared without synchronization.
    Only one caller today, but led_show_now() is public.
    Extended led_mutex to cover the whole led_push_hw, serializing
    against led_set_channel writers and any hypothetical
    concurrent pusher. rmt_transmit reads grb_buf asynchronously
    until rmt_tx_wait_all_done returns, so the buffer must stay
    intact for the full duration.

#76 FIXED -- WASM string pool and low heap fragmented over time.
    pool_free/low_heap_free only reclaimed the top allocation;
    adjacent freed blocks weren't coalesced. Long-running modules
    gradually exhausted the pool even when total free space was
    ample. Now coalesce forward and backward on free, shrink
    bump when the coalesced block is at the top, and prune
    trailing dead records (marked size=0, skipped by first-fit
    since min alloc is 4 bytes).

#77 FIXED -- printManager ANSI stripper only handled CSI.
    `ESC ]` (OSC — hyperlinks, window titles) and single-char
    ESC sequences (`ESC 7`, `ESC c`, etc.) landed in the log
    ring buffer / file sink / MQTT feed mangled. State machine
    rewritten to handle ESC [ ... final (CSI), ESC ] ... BEL|ST
    (OSC), and ESC X (single-char intermediate).

#78 FIXED -- effects.cpp function-scope statics persisted across switches.
    Transitioning between effects (or calling one after a long
    gap) left stale prev_sec / state / target_ms / step / offset_ms
    values that could trigger a spurious fire or skip. Moved all
    statics to module scope with s_* prefixes and added
    effects_reset_all() (declared in effects.h) to zero them.

ROUND 4 FIXES (2026-07-19)
==========================
Multi-agent code review of the full firmware tree. Fixes span the BASIC
interpreter, LED driver, WASM host layer, LoRa firmware-distribution
receiver, console/log, and config. Matching fixes were mirrored into the
Qt simulator (sim_wasm_imports_*, led_state.cpp) where the same code lives.

CRITICAL
--------

#80 FIXED -- BASIC array access gave scripts arbitrary heap read/write.
    bound() raised BOUNDS but still returned mem+n, and STOREI_/LOADI_
    dereferenced it before the driver checked globalerror. bound() now
    returns NULL on an out-of-range/non-array index and the opcodes bail.
    A(i) on an un-DIMed variable also compiled to STOREI_ with no mode
    check (NULL/scalar deref); opcodes now require a live DIM allocation.
    (basic.h)

#81 FIXED -- BASIC DIM double-free / free-of-scalar, within and across runs.
    freedim() freed on compile-time VARMODE_DIM, so a DIM in a dead branch
    -- or a re-DIM in the next program over the persistent symbol table --
    freed a stale or scalar value. Added runtime dim_alloc[] tracking:
    freedim() frees only real allocations and clears them, and initbasic()
    now frees leftovers and resets the symbol table per program.
    SETARRAY/SHIFTARRAY/ROTATEARRAY/SCALELIMITARRAY now validate with
    is_dim_ptr() instead of a bare !=0, closing an arbitrary-pointer
    read/write. SUB params/LOCALs bounded to LOCS; interp() no longer leaks
    the script FILE* on a compile error. (basic.h, basic_extensions.h)

#82 FIXED -- LED channel resize was a use-after-free.
    led_resize_channel() delete[]'d the old buffer outside led_mutex while
    ArtNet/BASIC/WASM/CLI writers held the raw leds* pointer with no lock.
    Buffers are now allocated once at boot to a fixed capacity; resize only
    moves the logical count within that capacity and never frees. Growth
    beyond the boot size returns -2 ("reboot to grow"). (led.cpp, commands.cpp)

#83 FIXED -- LoRa dist heap over-read from a crafted DIST_DATA chunk.
    finalize_block() read blk_comp_len / ulen bytes out of a blk_N*DIST_L
    buffer with no bound, so a chunk declaring a huge length forced an
    over-read (up to 64 KB from a 200-byte block). Now rejected. (dist.cpp)

#84 FIXED -- WASM printf/snprintf host imports leaked host stack / smashed a
    stack buffer. The copy loop ran to snprintf's would-be length (not the
    truncated count), so "%600d" read past tmp[] into host memory handed back
    to the guest; a long flag / *-width / precision run also drove the spec[]
    index past its buffer. Clamped the length and bounded spec[] (and added
    the -999..999 width/precision clamps). (wasm_format.cpp)

#85 FIXED -- WASM analog_read could brick PSRAM/LoRa SPI.
    adc_read_*/adc_ensure_channel accepted GPIO 1-10 and lazily configured
    any of them as analog; GPIO 4-7 (PSRAM) and 8-10 (LoRa) then lose SPI
    until power cycle. Restricted to GPIO 1-3 at the source (protects the
    WASM and BASIC analog_read and the CLI). (adc.cpp)

#86 FIXED -- WASM /config.ini write guard was bypassable.
    The exact-string check missed //config.ini and /./config.ini. Now rejects
    any path whose final component is config.ini. (wasm_imports_file.cpp,
    wasm_imports_compression.cpp, wasm_imports_deflate.cpp)

HIGH
----

#87 FIXED -- "load" held the print mutex across an unbounded, no-yield receive
    loop, stalling every printing task and starving the idle task into a WDT
    reset if a transfer hung. Now takes the lock only for the flush, polls
    with a yield + 30 s idle timeout, and writes a final line that has no
    trailing newline (previously dropped). (commands.cpp)

#88 FIXED -- "top" heap overflow when the task count grew mid-session.
    Only curr/order were reallocated on growth; the end-of-frame swap then
    made the smaller stale buffer the next curr and uxTaskGetSystemState()
    overran it. Now grows all three via realloc. (commands.cpp)

#89 FIXED -- log_open/log_close/log_free raced the vprintfnl sinks.
    Teardown ran without print_mutex, so a concurrent sink could fprintf/
    fclose a closing FILE*, or write to a freed ring and divide by a zeroed

#90 FIXED -- MQTT publisher task could publish on a destroyed client.
    mqtt_force_disconnect() esp_mqtt_client_destroy()'d s_client while the
    publisher task held and used it. Added a client mutex serializing the
    publish against the destroy. (conez_mqtt.cpp)

#91 FIXED -- inflate underflowed on truncated gzip input.
    data_len = in_len - off - 8 with no check that >= 8 bytes remain, so a
    truncated file produced a huge size_t and a massive over-read. Guarded.
    (inflate.cpp)

#92 FIXED -- LoRa dist manifest parsed with strtok_r over a non-terminated
    buffer. rx_buf was malloc(flen); strtok_r scanned past the end on every
    manifest reception. Allocate flen+1 and NUL-terminate before parsing.
    (dist.cpp)

OPEN (reported this round, not yet fixed)
-----------------------------------------

#101 FIXED -- BASIC PRINTS and FORMAT "$" dereferenced an arbitrary stack value
    as a C string (info leak / crash from e.g. `PRINTS 42`). In this tree-walk
    interpreter every string value is a pointer into the string table stab[]
    (string literals push (Val)(stab+off); there are no dynamic string ops), so
    added is_str_ptr(v) = (stab <= v < stab+STRSZ) and gated both derefs on it:
    PRINTS raises an error on a non-string arg, FORMAT "$" substitutes "(?)".
    (The earlier "inconsistency" note was a misread: FORMAT's format-string arg
    is a compile-time offset via need(STRING), while "$" value args are ordinary
    expression strings that push absolute stab pointers -- both correct.)

#102 FIXED -- GPS/time cluster (gps.cpp, nmea.cpp). Four issues:
    (a) the epoch anchor gated only on pps_count>0, so a module that stopped PPS
        but kept emitting NMEA time from its RTC made get_epoch_ms() run ahead
        without bound -- now also requires the PPS edge to be fresh (age <1.2s);
    (b) datetime_to_epoch_ms()==0 was stored unchecked (clock jumped to 1970) --
        now the anchor skips a zero result;
    (c) the anchor fired on any position update, so a GGA's new-day time paired
        with the previous RMC's date at UTC midnight and stepped back 24 h --
        nmea.cpp now bumps a datetime_count only on an RMC that carries a
        consistent date+time pair, and the anchor keys on that (never a GGA);
    (d) both ntp_loop() variants overwrote the epoch from the system clock even
        when SNTP had not synced this session -- since the ESP32 RTC survives
        soft resets, a stale >2024 clock clobbered the beacon/GPS/compile epoch.
        Now gated on ntp_last_sync!=0; unsynced, the display fields advance from
        the free-running epoch without overwriting it.

#103 FIXED (partly a mis-diagnosis) -- IMU tilt handling (sensors.cpp,
    mpu6500.cpp). CORRECTION: the original report claimed getRoll()'s +180
    offset was wrong and caused a permanent tilt alarm on every cone. That was
    based on a wrong assumption -- the PCB is mounted UPSIDE DOWN, so upright
    reads az = -1 g and the +180 is CORRECT (upright -> 0 deg). getRoll/getPitch
    were left as-is. The real, orientation-independent fixes: (a) the boot
    sanity check "in space" test now uses fabs(v_accZ) (works either way up);
    (b) mpu6500_calibrate() divides by the number of SUCCESSFUL samples (not a
    fixed 50) and targets +/-1 g on Z by the sign it actually reads, so running
    MPU_Calibrate on the upside-down device no longer flips the axis and creates
    the alarm; (c) mpu6500_read() returns success and sensors_loop() logs a
    sustained I2C failure instead of silently holding stale data (IMU is left
    uncalibrated in the field, so the calibration path was latent).

#104 FIXED -- Cue engine ordering + fix-validity (cue.cpp; mirrored in the
    simulator's cue_engine.cpp). The loop advanced a single monotonic cursor and
    broke at the first not-yet-due cue, but spatial offsets make effective start
    times non-monotonic, so one offset cue stalled every later cue. Replaced the
    cursor with a per-cue "fired" flag and a precomputed effective-start (offset
    is fixed for the run), scanning all cues each tick. cue_start() also gates
    spatial timing on a real GPS fix (get_gpsstatus()); with no fix it falls
    back to base start times instead of computing continent-scale offsets that
    would leave the cone dark.

#105 FIXED -- [HIGH] LUT double-free and TOCTOU heap overflow (util/lut.cpp,
    util/lut.h). lut.h exported pLUT/lutSize/currentLUTIndex as raw globals
    while lut_mutex was private, so BASIC's unlocked free(pLUT) raced
    loadLut()'s locked free and WASM's pLUT[index]=value -- double-free /
    use-after-free across BasicTask and WasmTask. The globals are now static;
    all access goes through locked accessors (lut_read/lut_write/lut_get_size/
    lut_current_index/lut_replace_from_array). loadLut()'s read loop is bounded
    by i<size against a file that changed since checkLut()'s count.

#106 FIXED -- [HIGH] Editor destroyed files longer than 512 lines on save
    (console/editor.cpp). editor_load() now sets a load_truncated flag when the
    file exceeds ED_MAX_LINES (or a PSRAM OOM cuts the load short), shows a
    READ-ONLY status, and editor_save() refuses so the original isn't
    overwritten with the truncated prefix.

#107 FIXED -- [HIGH] Unbounded dir/grep recursion on the 8 KB ShellTask stack
    (console/commands.cpp). dir_list/dir_max_name/grep_dir carried ~550 B of
    path buffers per frame and recursed to filesystem depth. Added a
    MAX_DIR_DEPTH (12) cap to all three.

#108 FIXED -- deflate LZ match finder was inert (util/deflate.c). Three coupled
    issues: (a) the current position was inserted as the hash-chain head before
    the search, and that head is also find_match's "candidate != dict_pos" loop
    sentinel, so the loop never ran, find_match always returned 0, and every
    byte was emitted as a literal (valid gzip but Huffman-only, ~2:1). Now
    find_match skips the just-inserted head (starts from NEXT). (b) Once matches
    fire, overlapping matches (dist < len) compared the lookahead against dict
    bytes at/after the write pointer that are stale -- now compared against the
    lookahead itself (cur_buf[len-dist]). (c) build_tree's max-bits
    oversubscription check computed a floored Kraft (repeated >>1) and missed
    every 1 < Kraft < 2 case; worse, a naive "reduce below 2^max_bits" fix left
    the lit/len tree INCOMPLETE (decoder rejects it). Replaced with the exact
    zlib gen_bitlen redistribution that brings the code to exactly complete.
    Verified with a host round-trip harness (PSRAM stub + gzip_buf) over
    empty/tiny/overlap/text/random/500KB/Fibonacci-skew/self-source inputs at
    all levels: every stream decompresses via system gunzip, and compressible
    data now shrinks ~10-300x (e.g. 500 KB repeated text 287 KB -> 1.3 KB,
    a real source file 62% -> 29%) where it was ~58-62% before.

#109 FIXED (5 of 7; 2 deferred) -- console/shell robustness (console/, util/).
    Fixed: (a) usb_write blocked 10 ms under print_mutex when no USB host was
    attached (full TX ring), throttling every task's console output -- now a
    cheap no-delay SOF-frame-counter check falls back to a non-blocking write

#111 FIXED -- PSRAM raw-transfer / timing / free (psram/psram.cpp, ConeZ
    improvised-PSRAM path). Three items:
    (a) tCEM budget [reachable]: a data chunk was sized to fill the full ~8 us
        max CE#-low time, but cs_low()/cmd.update sync/SPI2_WAIT hold CS# low
        around the clocking, so the transaction overshoots tCEM and risks DRAM
        refresh loss (bit decay) at temperature. Budget cut to 7 us (chunks
        ~35->30 B), leaving margin; chunk size floored at 1.
    (b) psram_free() double-free [reachable]: an untracked mapped (heap-fallback)
        address was free()d directly, so a fallback handle freed twice -- or
        freed after psram_free_all() released it -- was free()d again, corrupting
        the heap. Now only frees addresses still in the fallback table (a rare
        leak on table-full-at-alloc is the safe trade; PSRAM-range double-free
        was already safe via the block lookup).
    (c) 1 KB device-page crossing [defensive]: psram_raw_read/write now clamp
        each SPI burst to the 1 KB boundary so the chip can't wrap the tail. The
        cached path (the only raw-transfer user on ConeZ) was already safe --
        512-aligned 512-byte pages sit within one 1 KB page and the last chunk
        is len-truncated -- but this hardens the raw layer for the non-cached
        path (PSRAM_CACHE_PAGES=0) and any future direct caller.

#113 FIXED -- Config locking / web form (config.cpp). config_save now takes the

#115 FIXED -- Editor batched-keystroke corruption / OOB (console/editor.cpp).
    Input is drained in batches, so cy/cx could go stale (past the current
    line) before the next redraw clamped them. editor_enter then spliced
    post-NUL bytes into the split tail (garbage into the file), and -- worse

#116 FIXED (mitigated by reboot) -- get_epoch_ms() elapsed wrap (sensors/gps.cpp).
    elapsed = uptime_ms() - millis_at_pps is uint32 and wraps if the time anchor
    goes un-refreshed for 49.7 days, reporting a clock that jumps ~49.7 days
    backward. Only reachable on a cone with NO GPS/NTP/beacon for that long
    (running on the compile seed); any live time source re-anchors within
    seconds/hours and resets the age. A correct in-place fix would need a 64-bit
    anchor threaded through the PPS ISR's sub-ms edge capture -- untestable
    without hardware + a multi-week soak -- so instead time_check_wrap_reboot()
    (called from loop()) detects the impending wrap directly from the existing
    anchor age and reboots at ~48 days (just before the wrap) to re-seed the
    clock cleanly. No new state, no change to the epoch math; never fires on a
    healthy cone.

#57 FIXED -- Param ids clamped instead of rejected (basic/basic_wrapper.*).
    set_basic_param()/get_basic_param() clamped an out-of-range id to
    MAX_PARAMS-1, so a typo'd `param 99 1` silently overwrote param 15 -- which

#58 CLOSED (not applicable) + follow-on fix -- "check_serial() 512-byte buffer
    has no overflow protection" (util/shell.*).
    The reported bug does not exist and never did. check_serial() was deleted in
    c146127 (dual-stream CLI rewrite) and has no references left in the tree;
    both surviving historical versions had NO buffer at all -- they only polled
    Serial.available() and switched the output stream. There is no 512-byte
    buffer in any serial/command path (the only [512]s are in wasm_format.cpp,
    covered by round 3). The successor shell is bounds-checked at every entry:
    the keystroke path guards on SHELL_BUFSIZE-1, history recall uses
    strncpy(..., SHELL_BUFSIZE-1) + explicit NUL, the `pending` snapshot matches
    its source size, and execute(str)/executeExternal() copy exactly
    SHELL_BUFSIZE with explicit termination. SHELL_BUFSIZE is 88, not 512.

    What the audit DID turn up (fixed here) is silent truncation, not overflow:
      - The interactive path auto-submitted the line the moment it filled, so
        typing/pasting past 87 chars RAN a command the user hadn't finished --
        and dropped the rest. Now the line stops growing and refuses further
        keystrokes with a single BEL (one per fill, not per char, so a long
        paste doesn't machine-gun the bell); the line is only submitted on
        Enter, so what's on screen is exactly what runs. Tracked by a lineFull
        flag cleared in resetBuffer() and whenever there's room again.
      - execute(const char[]) silently truncated an over-long command to 87
        bytes and ran it. Since this is the MQTT `cmd` topic's entry point, a

        match a different path. Now rejected with "Command too long".
    The simulator has no parallel shell, so nothing to mirror.

#118 FIXED -- LoRa dist rejected every deflate-compressed block (regression from
    the #83 fix) (lora/dist.cpp).
    finalize_block()'s over-read guard rejected a block when EITHER the
    compressed length or the UNCOMPRESSED length (ulen) exceeded blk_N*DIST_L.
    But the master sizes N from the compressed length (N = ceil(comp_len /
    DIST_CHUNK_SIZE), conez-master.py), so ulen is legitimately larger than that
    for any block that deflates by a chunk or more -- i.e. essentially every
    firmware block and every compressible data file. Each one logged "len out of
    range" and was dropped on every pass, so LoRa firmware OTA could never
    complete (and held the OTA lock while it kept trying). Only blk_comp_len is
    a READ bound on blk_data; ulen is the WRITE bound on dest (already limited
    to rx_block_size within fw_block / rx_buf), and the store path requires
    blk_comp_len == ulen, so its memcpy is covered by the comp_len check alone.
    The ulen test is removed; the #83 over-read protection is unchanged.

#119 FIXED -- Raising an LED count at runtime overflowed the LED buffers
    (led/led.cpp + every LED writer).

#120 FIXED -- WiFi never reconnected after a drop or a failed first attempt
    (util/conez_wifi.cpp, main.cpp).
    The WIFI_EVENT_STA_DISCONNECTED handler only recorded the state, and
    esp_wifi_connect() was called solely from wifi_start()/wifi_reconnect()
    (boot and the `wifi` CLI). ESP-IDF does not retry by itself -- the Arduino
    layer used to, and the pure-IDF migration dropped that. So an AP reboot, or
    an AP that wasn't up yet at boot, left the cone "Disconnected" (no MQTT,
    NTP, ArtNet, telnet or HTTP) until a manual `wifi enable` or a reboot. New
    wifi_loop(), called from loop(), re-issues the connect while the state is

#121 FIXED -- Over-long MQTT commands were still truncated and executed
    (mqtt/conez_mqtt.cpp). Follow-on to the #58 fix.
    The MQTT event handler built the command into cmd[MQTT_CMD_MAX] (= 88) and
    simply stopped copying at 87 chars, so the string it queued was always
    shorter than SHELL_BUFSIZE and execute()'s "Command too long" check could
    never fire for the one caller it was written for. The payload was also
    clipped to 255 bytes before that, and a payload larger than esp-mqtt's
    512-byte buffer arrives fragmented (only the first piece carries the topic).
    The handler now computes the command length from the untruncated sizes
    (topic_len, total_data_len) and drops a command that doesn't fit: counted in
    the `mqtt` status "Cmd RX ... dropped" figure and logged as "cmd dropped: N
    chars, max 87". Nothing is clipped on the way to the shell any more.

#122 FIXED -- `mqtt connect`/`mqtt enable` raced the auto-start and could create
    two clients (mqtt/conez_mqtt.cpp).
    mqtt_force_connect() (ShellTask) cleared s_user_stopped and called

#123 FIXED -- A stalled upload hung the web server forever with the OTA lock held

#131 FIXED -- Heap overflow after a failed write during compression
    (util/deflate.c).
    flush_output() returned early once c->error was set, without resetting
    out_pos. emit_byte() relies on that call to make room, so every later byte
    was stored at out_buf[4096] and beyond -- over the rest of conez_deflate_t
    and into the heap. `deflate big.bin out.gz` on a nearly full filesystem, or
    deflate_mem into a too-small buffer, triggered it; the host test reproduced
    it as "free(): invalid next size". flush_output() now always empties the
    staging buffer (discarding after an error), and the stored-block loops stop
    on error.

#132 FIXED -- Corrupt .gz reported as success when the Huffman workspace could
    not be allocated (util/deflate.c).
    build_tree()'s malloc(~7 KB) fallback gave every used symbol an 8-bit code:
    incomplete or over-subscribed unless exactly 256 symbols are in use, and 8
    doesn't fit the 3-bit field of the code-length tree. gzip_stream() returned
    a size and inflate later rejected the file (host test: INVALID at every
    level). build_tree() now reports the failure and emit_dynamic_block() falls
    back to a fixed-Huffman block -- all three trees are built before any of
    the block is written, so the same LZ symbols go out as a valid, slightly
    larger stream.

#133 FIXED -- `psram cache` could deadlock the console (psram/psram.cpp).
    psram_print_cache_detail() held the PSRAM mutex across ~66 printfnl() calls
    (which take print_mutex), while every other task's printfnl() holds
    print_mutex and then writes the log ring through psram_write() (which takes
    the PSRAM mutex). Opposite lock orders: one debug line from loopTask at the
    wrong moment hung all console output, the shell and every PSRAM user until
    reboot. The cache metadata is now snapshotted under the lock and printed
    after it is released.

#134 FIXED -- psram_free() could double-free the system heap on boards without
    the improvised PSRAM (psram/psram.cpp: stub build = Heltec, and the native
    build).
    Those two branches called free() on any address missing from the tracking
    table -- so a handle freed twice, or freed after psram_free_all(), hit
    free() on memory already released. (#111 fixed this for the improvised
    path only.) The reason for the direct free() was that the fallback table
    could be full and hand out untracked pointers; psram_fb_malloc() now fails
    in that case instead, so every pointer handed out is tracked and an
    untracked address can simply be ignored in all three builds.

#135 FIXED -- The line editor printed nothing but its prompt with `color off`
    (console/editor.cpp).
    cmd_edit() runs line_editor() with interactive mode on, and printfnl()
    returns immediately in interactive mode -- but the line editor printed its
    banner, listings, usage, "Saved N lines" and every error through
    printfnl(). Only "edit> " and typed echo appeared. It now writes to the
    console stream directly under the print lock (le_printf), as AGENTS.md
    requires of interactive apps.

#136 FIXED -- Replace-all in the full-screen editor could spin forever
    (console/editor.cpp).
    After "a" the loop kept calling editor_find_next(), which wraps around the
    file, so it ended only when no match remained -- never, if the replacement
    contains the search text ("cone" -> "cone2") or a match sat on a line too
    long to grow. No delay, key check or pass limit: ShellTask at 100%, console
    dead, unsaved edits lost. "a" now runs editor_replace_all(): one pass over
    the file, resuming after the inserted text, counting matches it has to skip.

#137 FIXED -- Find missed a match at or before the cursor on the starting line
    (console/editor.cpp). The search started at cx+1 and visited each line
    once, so the first part of the starting line was never searched after the
    wrap ("Not found" for a sole match at column 0; nothing findable at or
    before the cursor in a one-line file). The start line is now visited again
    as a final pass, up to the cursor.

#138 FIXED -- Line editor `s old new` could truncate or wipe lines
    (console/editor.cpp). When a replacement would overflow the line, the loop
    broke without copying the rest and wrote back only the prefix; and `s  x`
    (two spaces) parsed as an empty search, which matches at every position and
    filled every line with the replacement. An over-long result now leaves the
    line unchanged and is reported; an empty search is refused.

#139 FIXED -- Editing a file with a line over 255 characters split that line on
    save (console/editor.cpp). editor_load() reads with fgets() into a 256-byte
    buffer, so a longer line arrived as several chunks stored as separate lines
    and editor_save() wrote a newline after each. Such a file now opens
    read-only (load_longline), like one with too many lines.

#140 FIXED -- Cut/paste acted on the wrong line when an arrow key and ^K/^U
    arrived in one input batch (console/editor.cpp). #115 added the cursor
    clamp (ed_sync_cursor) to insert/backspace/delete/enter but not to
    editor_cut_line()/editor_paste_line(): with cy == num_lines, ^K copied a
    stale slot past the end and deleted the real last line. Both now clamp
    first.

#141 FIXED -- WASM printf argument handling (wasm/wasm_format.cpp; simulator
    sim_wasm_imports_format.cpp for the parts it shared).
      - Doubles were read at the unaligned cursor. c2wasm stores a double (and
        long long) at an 8-byte-aligned offset, so printf("%d: %f", i, x)
        printed garbage and shifted every later argument -- on firmware only;
        the simulator already aligned.
      - "ll" was ignored: %lld/%llu read 4 bytes, printing the low word and
        leaving the high word to be taken as the next argument. Now an 8-byte
        aligned read for d/i/u/x/X/o. (The simulator had the same hole for
        %llx/%llX.)
      - %s went through a 128-byte copy, cutting strings at 127 characters,
        and its "(null)" branch could never run. It is now emitted straight
        from guest memory with width/precision applied; an out-of-bounds or
        unterminated pointer prints "(null)". The simulator truncated the same
        way (128-byte tmp) and is fixed too.
      - %E, %G and %o fell into the default case, which printed the specifier
        literally without consuming its argument. Now handled.

#142 FIXED -- WASM string/heap imports (wasm/wasm_imports_string.cpp;
    simulator sim_wasm_imports_string.cpp mirrored).
      - MID$ with a huge count ("rest of string", e.g. 2147483647): `s + n >
        slen` overflowed, so the count was never clamped and pool_alloc(n + 1)
        wrapped to a 4-byte block -- an empty result with PSRAM, a wild host
        write without it (and an unclamped memcpy in the simulator). Clamp is
        now `n > slen - s`, and pool_alloc/low_heap_alloc reject sizes that
        can't fit before rounding.
      - str_len / str_concat / the source of MID$ assignment called
        wasm_mem_strlen() on pointer 0, scanning real memory at offset 0 (the
        start of the data segment), so an unassigned BASIC string read as
        whatever literal was there. Pointer 0 is now an empty string, as in the
        simulator.
      - realloc() sent any pointer below 0x8000, including NULL, to the low
        heap with no fallback, so it failed where malloc() succeeds (low heap
        disabled, full, or out of its 32 records). realloc(NULL, n) now behaves
        as malloc, and a low-heap block that can't grow moves to the pool.
      - Both allocators handed out a whole free block without splitting it and
        reclaimed dead (size 0) records only when they were last in the table,
        so a long-running program could report out-of-memory with most of the
        28 KB pool free. Free blocks are now split and dead records reused.

#143 FIXED -- larpf()/larp() could hang the WASM task for good (util/curve.cpp;
    simulator sim_wasm_imports_math.cpp mirrored).
    larpf's `for (float s = ...; s <= ...; s += step)` stops advancing once
    step is below half a float ULP of s -- x_pos = millis() after ~28 h is
    enough -- and it runs inside a host import that `stop` cannot interrupt.
    larp() had the integer equivalents (overflow of `i += stride`, billions of
    iterations for a huge window). Both now compute a sample count up front,
    loop on an integer index, and cap it at LARP_MAX_SAMPLES (4096), widening
    the spacing past that.

#144 FIXED -- BASIC interpreter (basic/basic.h, basic_extensions.h). NOT BUILT
    in either default target (no INCLUDE_BASIC); checked with a syntax-only
    compile of basic_wrapper.cpp with the flag on, not a full build or a run.
    The interpreter did not compile at all before this (`else PCV;` in FOR_ is
    -Werror=unused-value) -- fixed with a (void) cast.
      - Zero-argument functions (VERSION, GETMAXLED, HASGPS, HOUR, UPTIME,
        SUNAZ, ... ~40 of them) do `*sp = value` with no argument pushed, so
        they overwrote the top of the stack -- the saved return address inside
        a SUB, or stk[STKSZ] at top level. funhook_exec_() now pushes a
        placeholder slot before a zero-argument function.
      - After a runtime error interp() never returned: check_error() only
        treats a fault as fatal while `filen` is set, and it is cleared before
        the program runs. BasicTask fell into the interactive prompt, stole
        console input from the shell, never picked up the next `run`, and never
        released the CPU PM lock. A fault in a program run from a file now
        returns 2.
      - A stray ELSE, END, NEXT or WEND read and wrote past the compile stack
        instead of reporting an error (ELSE also patched prg[<garbage>]; a
        second ELSE patched prg[0]). They are validated first ("ELSE WITHOUT
        IF", "ELSE AFTER ELSE", "END WITHOUT BLOCK", ...). CSP_CHECK now takes
        the number of entries about to be pushed (it reserved one slot while
        SUB/WHILE/IF push three and FOR four).
      - SCALE() with equal input bounds divided by zero in map(), which panics
        the board. It now returns the low output bound.
      - initbasic() did not reset lnum, temp, ipc, opc, ungot or ret, so line
        numbers in errors kept counting across runs and a load aborted inside a
        FOR made the next program's RETURN emit a spurious DROP_.
      - ROTATEARRAY on a zero-length array wrote outside its allocation (or
        over its own size header). Arrays of 0 or 1 elements are a no-op.
      - An unterminated string literal stepped the lexer past the end of the
        line into stale bytes. Now "UNTERMINATED STRING".
      - FORMAT wrote to the raw stream instead of printfnl(), skipping the
        debug-source gate, the log/MQTT sinks and the interactive-mode mute.

#145 FIXED -- Minor.
      - `psram test` refused to run once any WASM script had run (the
        preallocated linear memory lives in PSRAM until reboot) and nothing
        kept other tasks out of PSRAM while it overwrote the chip. cmd_psram
        now releases the prealloc (wasm_prealloc_release(), refused while a
        script runs; re-created on the next run), and psram_test() claims the
        chip under the lock and routes new allocations to the system heap until
        it finishes.
      - The PSRAM page cache's 32-bit LRU clock had no wrap handling: after
        2^32 accesses fresh pages got the smallest timestamps and were evicted
        first. On wrap the pages are renumbered in LRU order.
      - deflate's 3-byte match hash masked (b0 | b1<<8 | b2<<16) to at most 15
        bits, discarding b2 entirely. Replaced with a multiplicative hash; on
        the host test a 1.2 MB text input at level 1 went from 374 KB to
        347 KB (levels 6/9 within 1%).
      - gzip_stream() clamped `level` only inside deflate_alloc(); a negative
        level would have skipped the table allocation but taken the LZ path.
        Clamped up front (no current caller passes one).
